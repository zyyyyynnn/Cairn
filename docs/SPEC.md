## 1. 产品定位与核心目标

### 1.1 产品定义
**Cairn** 是一款面向 Windows 10 (1809+) 与 Windows 11 (x64) 的开源（`Apache-2.0`）、中英双语、高性能本地文件即时检索与安全管理桌面工具。
- **底层内核**：直接流式读取 NTFS 卷主文件表（`$MFT`）建立紧凑常驻内存索引，通过 USN 变更日志（USN Change Journal）保持近实时增量追赶，并提供进程隔离的可选 Tantivy 全文检索支持。
- **桌面表现**：基于 Rust + GPUI Kit（`gpui-kit`）构建高密度桌面界面，提供结构化导航、毫秒级检索、灰阶语义令牌、中文输入法（IME）适配与键盘操作。
- **单向解耦**：内核引擎、后台服务与界面交互严格单向分层解耦，服务坚守只读安全边界，桌面端可通过标准接口独立演进或替换。

### 1.2 目标用户与使用场景
- **目标用户**：中文环境下的开发者、系统运维工程师与重度文件管理用户，单机文件规模通常在数十万至数千万级别。
- **典型场景**：
  1. 通过模糊子串、复合逻辑（`AND`/`OR`/`NOT`）或正则表达式，在 400 万条索引下以常见查询 P95 ≤ 30ms 定位项目代码、工程构件或文档；单机文件规模目标为数千万级；
  2. 依赖 `size:`、`dm:`/`dc:` 等时间与大小谓词快速排查大文件或近期变更；
  3. 基于 `content:` 语法在指定代码仓或文档目录下精准检索含特定文本或标识符的文件内容；
  4. 纯键盘无鼠标流转完成打开、所在目录资源管理器定位、路径复制、安全重命名与安全移入回收站。

### 1.3 核心设计目标
1. **速度与资源标杆**：文件名搜索中位延迟与常驻内存基准全面对标并力争超越 Everything 1.4。
2. **零静默过期原则**：文件系统变更近实时反映至搜索结果；当卷处于任何非同步状态时，协议与界面必须显式标注，**严禁在非同步状态下静默返回过期数据**。
3. **中文输入法原生态体验**：解决 GPUI/Zed 在 Windows 下中文输入法的组合丢字、重复上屏与候选窗错位问题。
4. **服务只读与操作安全**：后台特权服务坚守 100% 只读红线，杜绝提权写漏洞；写操作由免提权客户端直接调用系统原生 Win32 `IFileOperation` 安全执行。
5. **可验证性与门禁闭环**：性能、内存与一致性结论以可复现的基准、集成测试或明确标注的手工验收为准。

### 1.4 北极星成功指标（North Star Metrics）

| 编号 | 核心维度 | 对标基准与量化验收标准 |
|:---|:---|:---|
| **SM-1** | **文件名搜索速度** | 同机、同语料、同查询集（≥10 条典型查询，均按名称排序取完整结果集，预热 2 次取 6 次中位数）对比 Everything 1.4，查询中位延迟不劣于 Everything；400 万条下常见查询首屏 **P95 ≤ 30ms** |
| **SM-2** | **常驻内存占用** | 400 万条索引下，`CairnService` 服务常驻内存不高于 Everything 1.4（基础索引 **≤ 125 字节 / 条**，400 万条约 500MB；每个预排序索引 **4 字节 / 条**）；GUI 空闲内存 **≤ 150MB** |
| **SM-3** | **中文输入法兼容性** | 在微软拼音、搜狗拼音、微信输入法 3 款主流输入法下，搜索框组合输入零丢字、零重复上屏，候选窗精确跟随光标且不遮挡输入行（完整通过 [engineering/quality.md](engineering/quality.md) 专项测试清单） |
| **SM-4** | **增量同步实时性** | 文件创建、重命名、删除、移动后可被搜索到的端到端延迟 **P95 ≤ 1.5 秒**；已索引文件内容修改后 **≤ 10 秒** 可被全文检索命中 |
| **SM-5** | **索引状态与一致性** | 1 万组随机文件操作序列下，USN 增量更新索引与 `$MFT` 全量重建结果 **零差异**；卷处于非同步状态时必须显式标注，**严禁在非同步状态下静默返回过期数据** |

## 2. 范围、优先级与能力基准

### 2.1 系统约束
- **运行平台**：Windows 10 (1809+, OS Build 17763+) 及 Windows 11，仅支持 x64 架构。
- **开发与构建环境**：Rust Stable（严格锁定于根目录 `rust-toolchain.toml`），Windows 11 + PowerShell 7+，UTF-8 字符集。
- **架构模式**：后台 Windows 服务固定以 `LocalSystem` 运行（读取裸盘 `$MFT`/USN、维护受保护索引） + 免提权桌面 GUI 客户端，通过本地 Win32 命名管道进行 IPC 通信。**安装完成后由 SCM 自动启动服务；日常启动 `Cairn.exe` 采用标准用户权限，无需管理员提权。** 服务不可达时 GUI 先尝试一次免 UAC 的 SCM 静默启动；仍不可用时保留表头与工作区，结果区显示单行离线态以及启动或重试入口。运行期唯一可能提权的动作是该离线态在服务已安装但未运行时提供的显式启动恢复入口。
- **界面语言**：简体中文（`zh-CN`）与美式英文（`en-US`），默认跟随操作系统的语言设置并支持界面手动切换。
- **开源许可**：全工作区遵循 `Apache-2.0` 开源许可证。

### 2.2 优先级划分（Milestones）

| 优先级 | 范围与包含特性 |
|:---|:---|
| **P0 (核心基础)** | 本地固定 NTFS 卷 `$MFT` 流式索引、USN 增量同步与故障重建、Everything 核心语法（与或非/引号/通配符/大小写/全字/匹配路径/正则）、四段式现代高密度灰阶 GUI、后台 Windows 服务（`CairnService`）、中英双语（`fluent-bundle`）、中文输入法（IME）四大缺陷根治、纯文本内容检索 |
| **P1 (完善增强)** | 富文档（`docx`/`xlsx`/`pptx`/`pdf`）抽取与 Worker 进程隔离、命中片段切片高亮渲染、快速过滤器内置宏、系统托盘与全局热键唤起、免提权 CLI 查询工具（`cairn-cli`）、GPUI Setup + WiX MSI 单文件安装包（`CairnSetup.exe`）工程与构建溯源 |
| **P2 (生态演进)** | Everything IPC / `es.exe` 兼容适配层、FAT32 / exFAT 卷轮询扫描、ReFS 卷支持、中文拼音与首字母搜索（`py:`）、Windows 系统 IFilter 原生接入、系统级文件预览窗格、ARM64 架构构建支持 |

### 2.3 边界与非目标（Non-Goals）
1. **服务只读红线**：后台提权服务绝对不提供任何修改文件系统（写入、重命名、删除、移动）的管道接口，防止特权服务沦为写操作攻击面。
2. **免提权客户端安全操作**：仅允许在免提权 GUI 进程中，通过 Windows 原生 Win32 `IFileOperation` / `SHEmptyRecycleBin` API 规范触发删除到系统回收站、从回收站还原、永久删除与清空回收站，由 Windows Shell 原生承载进度与错误；日常删除与永久删除使用项目统一确认框，清空回收站保留 Windows 原生警告。严禁向后台服务暴露写管道。
3. **平台与介质边界**：首版聚焦本机固定 NTFS 卷，不包含 macOS、Linux、云盘同步盘、网络共享（SMB/ETP）、远程查询管道。
4. **功能边界**：不引入语义 / AI 向量搜索、OCR 图片文字识别、远程遥测上报、用户账号体系或动态外部插件系统。

### 2.4 能力判据体系（Criteria）
1. **三档打通判据**：一项能力必须在**语法（core 解析器识别）**、**执行（service/engine 实际过滤）**与**界面可达（GUI/CLI 具备入口且反馈）**三档全部打通，才判定为“已具备”。代码存在但无调用入口的标记为“待接线”。
2. **一手出处判据**：所有对标能力必须具备官方支持文档或作者发布公告等一手证据，严格区分 Everything 1.4 已有与 1.5 新增特性。
3. **排除项边界**：明确不采纳 Everything 网络供数面（ETP/HTTP Server/SDK 外部供数）、遍历型工具特征（gitignore 规则、目录深度限制 `fd -d`）以及终端 TUI 范式（分屏、终端颜色）。

## 3. 九域能力基准与现状清点

基于 [research/references.md](research/references.md) 所列一手调研文献，系统梳理同类产品能力矩阵及 Cairn 当前代码的实际闭环状态：

### 3.1 检索模型（Search Model）
- **同类基线**：子串匹配、正则表达式、通配符（`*`/`**`/`?`）、大小写控制、路径匹配开关是桌面与 CLI 检索工具（Everything、fd、ripgrep、fzf）的通用基线。
- **差异化能力**：Everything 1.5 引入的标点忽略（`ignore-punctuation:`）、空白忽略（`ignore-whitespace:`）、前后缀词边界（`prefix:`/`suffix:`）及变音符号控制（`diacritics:`）。
- **Cairn 闭环现状**：
  - `case:`、`ww:`、`path:`、`regex:`、通配符、逻辑组合（`!`、`|`、`<...>`、`"..."`）三档全通。
  - `prefix:` 与 `suffix:` 词边界匹配已在 `cairn-core/src/engine.rs` 完整实现。
  - 日期函数 `dm:`/`dc:` 全面支持相对时长（`2days`）、ISO 日期、`YYMMDD`、月份星期名常量及 `mtd/ytd/qtd`。
  - 正则查询已接入缓存机制，避免逐行重新编译导致性能退化。

### 3.2 列与元数据（Columns & Metadata）
- **同类基线**：Everything、Files App 与 eza 均支持多列长格式展示，名称、路径、大小、修改时间为核心基准列。
- **差异化能力**：列宽自适应记忆、表头右键动态显隐扩展列（创建时间、扩展名）、内容派生元数据（代码行数、音频标签）。
- **Cairn 闭环现状**：
  - 虚拟表格稳定渲染名称、路径、大小、修改时间四列，列宽比例与数值对齐符合规范。
  - 排序列与排序方向已接入 `%APPDATA%\Cairn\settings.toml` 读写；四列宽度可拖动表头分隔线调整，并在释放时回写同一配置、下次启动恢复。
  - 文件名与路径命中区间切片高亮：`query_orchestration.rs` 切片、`results_view.rs` 渲染。
  - 系统原生图标缓存尚未接入；当前表格使用扩展名语义矢量图标以保障高密度性能（接线项）。

### 3.3 导航结构（Navigation Structure）
- **同类基线**：Files App 采用 `Omnibar` 整合面包屑与搜索；现代文件管理器普遍配备可折叠导航侧栏。
- **Cairn 闭环现状**：
  - 侧边栏支持由按钮收起/展开；收起/展开的快捷键尚未绑定（待接线）。
  - 侧栏类型过滤（8 大分类）与卷作用域切换完全打通。
  - 主搜索框全宽延伸，直连数据表头。

### 3.4 筛选与分面（Filters & Facets）
- **同类基线**：类型宏、扩展名集合筛选、按文件大小与日期区间分面过滤。
- **Cairn 闭环现状**：
  - 8 大分类快速过滤器（所有、音频、文档、可执行、图片、视频、压缩包、文件夹）支持快捷键与界面点击无缝联动。
  - `size:`、`ext:`、`dm:`/`dc:` 函数全面执行过滤。
  - 隐藏/系统属性过滤已在引擎层实现，但 MFT 扫描尚未写入属性位、GUI 也未提供开关（待接线，见 §3.10-3）；路径排除规则可在配置文件中声明。

### 3.5 结果操作（Result Operations）
- **同类基线**：打开、资源管理器定位、复制路径、系统属性面板为基线操作；现代桌面端必备安全删除至回收站与重命名。
- **Cairn 闭环现状**：
  - 数据表右键上下文菜单（打开、重命名、打开所在位置、复制完整路径、复制文件名、删除、系统属性）与 Treemap 右键菜单闭环。
  - 后台服务 100% 只读；GUI 侧已通过 Win32 `IFileOperation` 实现删除到回收站，并提供回收站位置视图（浏览、还原、永久删除、清空回收站）。
  - 协作式查询取消（`Cancel`）已闭环：GUI 停止当前查询时发送当时查询的 id；同一客户端的新查询取代其旧查询，服务端以客户端进程与查询 id 为键的活动查询注册表精确取消，其他客户端的查询不受影响。取消是停止状态，状态轮询不会复活它，只有新的输入或位置切换重新发起查询。

### 3.6 选择与键盘（Selection & Keybindings）
- **同类基线**：全键盘可达、焦点循环、快捷键覆盖率高是高生产力工具的核心标准。
- **Cairn 闭环现状**：
  - 核心快捷键已绑定：`Ctrl+F`/`Alt+D`/`F3` 聚焦、`Tab` 切焦点、`Ctrl+Shift+C` 复制全路径、`Ctrl+Shift+N` 复制文件名、`Ctrl+C` 复制选中文本或路径；Treemap 画布缩放可用（画布聚焦时生效）：`Ctrl+0` 复位、`Ctrl+=`/`Ctrl+-` 逐级缩放，状态栏另有复位按钮。未接线：应用级界面缩放还没有键盘入口。
  - 单选、Ctrl 多选与 Shift 连续区间选择已实现（支持鼠标点击与方向键连续多选）。
  - 命名互斥体单实例与托盘显示/退出已实现；全局热键 `Ctrl+Alt+Space` 呼出/隐藏主窗口，组合被占用时启动提示一次，托盘入口保持可用。

### 3.7 索引引擎与规模（Indexing & Scale）
- **同类基线**：流式读取 `$MFT` 结合 USN 变更追赶，无日志卷支持快照降级。
- **Cairn 闭环现状**：
  - 盘符枚举与流式分块读取 MFT 已实现；卷 GUID 当前是占位值（`VOL_C:`），`$BITMAP` 预跳过尚未实现（待接线）。
  - USN Journal 常态 500ms 轮询、追赶期 50ms 轮询，删除事件优先判定。
  - 无日志卷自动降级为 `SnapshotMode` 快照模式并支持低频定时重新扫描。
  - 索引持久化缓存具备魔数、版本头与校验和，写盘采用原子替换。

### 3.8 系统与平台集成（System Integration）
- **同类基线**：后台 Windows 服务（LocalSystem）常驻维护多卷索引，免提权 GUI 客户端通过安全 IPC 通信。
- **Cairn 闭环现状**：
  - `CairnService.exe` 服务具备 Win32 DACL 严格安全描述符与 `PIPE_REJECT_REMOTE_CLIENTS`，仅允许本地交互用户连接。
  - 管道显式校验版本护栏，防止反序列化漏洞。
  - 索引配置由本地已认证用户经管道提交，服务校验后以 SYSTEM/Administrators 描述符原子持久化并即时应用：`SetConfig` / `GetConfig` / `ClearContentIndex` 界面可达；`Rescan` / `ReloadConfig` 的服务端 handler 与鉴权已实现并有测试，界面与 CLI 均不发出（待接线，见 §3.10-7）；`admin_only_query` 只能由管理员修改。

### 3.9 本地化与偏好设置（Localization & Settings）
- **同类基线**：完整的多语言国际化架构（非硬编码），偏好设置持久化。
- **Cairn 闭环现状**：
  - `fluent-bundle` 双语支持（`zh-CN.ftl` / `en-US.ftl`），键值 100% 对齐。
  - `%APPDATA%\Cairn\settings.toml` 原子读写持久化，语言、排序列、列宽、字体缩放、开机自启生效。
  - Windows 当前用户开机自启（写入 Run 注册表键）打通。

### 3.10 能力状态与差距清单（Status & Gaps）
以下条目不计为“达标”，必须按实际状态对待：
1. **系统原生图标**（待接线）：原生图标缓存尚未接入，结果表当前使用扩展名语义矢量图标。
2. **内容检索命中片段（Snippet）**（部分达标）：服务端已产出上下文片段；GUI 以内容命中 badge + hover tooltip + ARIA 描述呈现，尚无独立片段面板与匹配词高亮区间。片段只由正极性内容词提供；逐记录布尔慢路径中，单个正向内容词命中达到检索上限（5 万条）时该词只保留命中集，其独占命中的行不显示内容标识；纯内容析取的并集命中达到检索上限时整条查询只保留命中集，所有行不显示内容标识；正向合取的截断回复仍携带返回行的片段。单条查询至多 16 个内容词（`MAX_CONTENT_TERMS`，按解析后带内容检索的项数计，含重复与否定项）；超限查询在管道请求边界以错误码 416 整体拒绝，GUI 在结果空态说明拒绝原因。
3. **隐藏/系统属性**（待接线）：引擎过滤已实现，但 MFT 扫描未写入 `FLAG_HIDDEN`/`FLAG_SYSTEM`，GUI 也无开关（见 §3.4）。
4. **GUI 写操作面**（部分达标）：删除到回收站、回收站浏览/还原/永久删除/清空已实现；结果表恰好选中一行时，`F2`、文件菜单、结果右键菜单可就地重命名（GUI 内 `IFileOperation`，索引由 USN 自然更新）；后台服务保持只读。
5. **表头显隐**（未实现）：列显隐与表头右键菜单未实现；列宽拖拽与持久化已落地。
6. **全局热键**：`Ctrl+Alt+Space` 呼出/隐藏主窗口；组合键被占用时启动提示一次，托盘入口保持可用。
7. **手动重扫与配置重载**（待接线）：协议、服务端 handler 与鉴权已实现并有测试，GUI 与 CLI 都没有发出 `Rescan` / `ReloadConfig` 的入口。
8. **离线 MFT 镜像**（未实现）：IDX-10 要求的从 `$MFT` 镜像离线构建与验证索引尚无入口；当前仅支持在线卷读取。
