# 性能与非功能需求

> 本文定义 Cairn 的非功能性需求（NFR）与性能指标。每次发布前按 release 构建重测，并在报告中注明 commit、硬件和样本规模。

## 1. 非功能需求（NFR）

| 编号 | 类别 | 指标量化阈值 |
|:---|:---|:---|
| **NFR-01** | 首次全量索引速度 | 400 万条记录、NVMe 固态硬盘：首次全量建索 **≤ 15 秒**；机械硬盘（HDD）平稳上报构建进度 |
| **NFR-02** | 启动缓存加载耗时 | 400 万条记录索引落盘缓存加载与校验 **≤ 3 秒** |
| **NFR-03** | 查询响应延迟 | 匹配命中数 ≤ 10 万的典型查询，首屏返回 **P95 ≤ 30ms**；全量匹配查询首屏 **P95 ≤ 100ms**，排序执行惰性分页计算（预算针对文件名与元数据查询；含 `!` / `|` 的内容布尔查询属慢路径，见 §2.3）。该预算以 400 万条索引语料为基础，与 SM-1 同口径；10 万命中是预算适用的结果规模范围，不是系统结果上限 |
| **NFR-04** | 界面渲染帧率 | 键盘输入到首屏像素渲染完成（包含 50ms 输入合并窗口与 IPC 往返）**P95 ≤ 80ms**；100 万行结果表格虚拟滚动稳定 **≥ 60 FPS** |
| **NFR-05** | 后台服务内存基准 | 包含名称、大小、时间的基础索引内存常驻 **≤ 125 字节 / 条**（400 万条约 500MB）；启用 3–5 个高频属性索引的配置目标 **≤ 160 字节 / 条**，需在 400 万条语料单独实测；未启用属性索引时不得增加常驻内存；每个预排序索引仅占 **4 字节 / 条** |
| **NFR-06** | GUI 客户端内存 | 免提权 GUI 客户端空闲常驻内存 **≤ 150MB** |
| **NFR-07** | CPU 资源消耗 | 文件系统无变更时，后台服务与 Worker 处于完全休眠状态，CPU 占用率 **< 1%** |
| **NFR-08** | 增量更新延迟 | 实盘文件产生变更后，增量追赶并入内存索引的端到端延迟 **P95 ≤ 1.5 秒** |
| **NFR-09** | 可靠性与故障自愈 | 服务崩溃由 Windows SCM 自动重启；索引文件损坏自动检测并单卷自愈重建；写盘严格执行“写临时文件 + 原子替换” |
| **NFR-10** | 隐私与数据安全 | 坚持**零遥测、零后台回传**；除用户主动触发的更新检查外不发起网络请求；内容索引默认关闭，只有用户显式开启后才对所有已索引卷中符合扩展名/大小上限的可读文件建立本地内容索引；不读取未纳入索引的卷 |
| **NFR-11** | 无障碍可访问性 | 所有核心交互控件具备规范的 Accessible Name 与 Role（基于 AccessKit），无障碍测试纳入 CI 门禁 |

## 2. 性能与内存设计约束

### 2.1 流式与虚拟化

- 查询结果通过命名管道会话游标分页，避免一次性反序列化超大结果集；无过滤全卷视图直接切片返回，带排除规则的全卷视图通过 `AllFilesView` 懒构建 1,024 槽位块前缀数组（`OnceLock<Box<[u32]>>`），将深翻页定位开销控制在 $O(\log(N/B) + B)$。
- 结果表使用虚拟列表，只渲染可见行；行高按 `rems(layout::ROW_HEIGHT)`（`ROW_HEIGHT` 换算自 `28px / BASE_FONT_PX`，100% 缩放下为 `28px`）随界面缩放等比换算，滚动时窗口化请求；行右键菜单挂载在共享结果栈容器（`result-rows-stack`），滚动帧不为逐行重建菜单状态与焦点句柄。
- 搜索/过滤不在 `render` 中触发异步分页；使用偏移变化钩子或 `defer`，带防重入标记。

### 2.2 常驻内存模型

- 文件节点保持紧凑：文件 ID、父目录 ID、属性标志、修改时间、大小等必要字段。
- 文件名进入共享字符串池/紧凑缓冲，避免每节点独立堆分配。
- 排序使用预构建副索引或并行排序，避免动态全表深拷贝；大量变更时标记脏数据并在合适时机重建。
- 服务/索引器的锁范围要短；管道读写带超时、背压和取消。
- 属性索引使用按来源/记录键的侧表，由 `CairnWorker` 内的纯 Rust 解析器抽取，带超时隔离与失败降级；未启用时不分配。100k 基础基准门禁只覆盖基础配置，属性索引开启后的内存与查询需单独基准。

### 2.3 内容查询路径

- 单条查询至多 16 个内容词（`cairn_core::syntax::MAX_CONTENT_TERMS`，按解析后带内容检索的项数计，含重复与否定项）。布尔求值为每个去重后的内容词构建记录索引位图，并在每条记录上求值每次出现，词数上限即单查询的内存与扫描成本上限；管道请求边界对超限查询以错误码 416 整体拒绝，GUI 在结果空态说明拒绝原因。
- 正向合取（`content:a content:b`、`ext:rs content:x`）用 FAST 字段收集完整命中集，再与 MFT 元数据过滤求交；不按 top-k 截断，避免过滤后丢失低分匹配行。
- 纯内容析取（整条表达式为两个及以上单项内容词作 `|`）走一次 Tantivy 联合检索：FAST 字段收集并集命中集，按卷解析为一张记录索引位图后产出匹配行，排除规则与布尔慢路径一致。
- 其余含 `!` 或 `|` 的布尔组合（否定、元数据分支、嵌套分组）需要每个内容词的完整命中集，再逐记录布尔求值。否定词与正向词都以 FAST 字段收集 `(volume_id, frn)`。锁内命中成员按记录索引位图解析（每词一张，硬链接的每条记录各占一位），每个 FRN 列表在其位图建成后立即释放，解析按并行分块进行。
- 该布尔求值持有卷读锁，成本随内容词数与索引规模线性增长，属于慢路径，不受 NFR-03 的 30ms/100ms 预算约束（预算覆盖文件名与元数据查询）。
- 内容命中标识（badge、tooltip、ARIA 描述）依赖非空片段；片段只为返回结果的前 5 万行生成（`CONTENT_RESULT_TOP_K`），窗口外的命中行不显示内容标识。否定词从不提供片段，避免给经其他分支命中的行贴上误导的内容标识。

### 2.4 测量与报告

- 先构建 release，再记录冷启动、查询、首帧与常驻内存。
- 报告区分“测量值”和“目标值”；未执行或环境不满足时明确写“未验证”。
- 任何优化必须给出前后对比和回退条件，不以单个平均值替代分位数/边界样本。
