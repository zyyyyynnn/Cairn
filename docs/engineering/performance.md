# 性能与非功能需求

> NFR 是规格目标，不是当前发布版本的实测承诺。每次发布前按本机 release 构建重测，并在报告中注明 commit、硬件和样本规模。

## 1. 非功能需求（NFR）

| 编号 | 类别 | 指标量化阈值 |
|:---|:---|:---|
| **NFR-01** | 首次全量索引速度 | 400 万条记录、NVMe 固态硬盘：首次全量建索 **≤ 15 秒**；机械硬盘（HDD）平稳上报构建进度 |
| **NFR-02** | 启动缓存加载耗时 | 400 万条记录索引落盘缓存加载与校验 **≤ 3 秒** |
| **NFR-03** | 查询响应延迟 | 匹配命中数 ≤ 10 万的典型查询，首屏返回 **P95 ≤ 30ms**；全量匹配查询首屏 **P95 ≤ 100ms**，排序执行惰性分页计算 |
| **NFR-04** | 界面渲染帧率 | 键盘输入到首屏像素渲染完成（包含 IPC 往返）**P95 ≤ 80ms**；100 万行结果表格虚拟滚动稳定 **≥ 60 FPS** |
| **NFR-05** | 后台服务内存基准 | 包含名称、大小、时间的基础索引内存常驻 **≤ 125 字节 / 条**（400 万条约 500MB）；每个预排序索引仅占 **4 字节 / 条** |
| **NFR-06** | GUI 客户端内存 | 免提权 GUI 客户端空闲常驻内存 **≤ 150MB** |
| **NFR-07** | CPU 资源消耗 | 文件系统无变更时，后台服务与 Worker 处于完全休眠状态，CPU 占用率 **< 1%** |
| **NFR-08** | 增量更新延迟 | 实盘文件产生变更后，增量追赶并入内存索引的端到端延迟 **P95 ≤ 1.5 秒** |
| **NFR-09** | 可靠性与故障自愈 | 服务崩溃由 Windows SCM 自动重启；索引文件损坏自动检测并单卷自愈重建；写盘严格执行“写临时文件 + 原子替换” |
| **NFR-10** | 隐私与数据安全 | 坚持**零遥测、零回传、零网络通信**；内容索引默认关闭，只有用户显式开启后才对所有已索引卷中符合扩展名/大小上限的可读文件建立本地内容索引；不读取未纳入索引的卷 |
| **NFR-11** | 无障碍可访问性 | 所有核心交互控件具备规范的 Accessible Name 与 Role（基于 AccessKit），无障碍测试纳入 CI 门禁 |

## 2. 性能与内存设计约束

### 2.1 流式与虚拟化

- 查询结果通过命名管道会话游标分页，避免一次性反序列化超大结果集。
- 结果表使用虚拟列表，只渲染可见行；行高 `28px` 固定，滚动时窗口化请求。
- 搜索/过滤不在 `render` 中触发异步分页；使用偏移变化钩子或 `defer`，带防重入标记。

### 2.2 常驻内存模型

- 文件节点保持紧凑：文件 ID、父目录 ID、属性标志、修改时间、大小等必要字段。
- 文件名进入共享字符串池/紧凑缓冲，避免每节点独立堆分配。
- 排序使用预构建副索引或并行排序，避免动态全表深拷贝；大量变更时标记脏数据并在合适时机重建。
- 服务/索引器的锁范围要短；管道读写带超时、背压和取消。

### 2.3 Treemap 性能

- 有索引时经 `GetTree` 一次往返取得聚合树；回退的本地扫描按目录级工作窃取并行，等完整树就绪后一次呈现。
- 树节点只保存自身名称，不保存完整路径：省去整树为每个后代复制祖先前缀的开销（全盘树的主要内存成本），路径仅在布局层为可见 tile 物化，树内查找按名字段下降。
- 完成的根树由视图与缓存经 `Arc` 共享同一份分配，扫描折叠经 `Arc::make_mut` 写穿。
- 布局只对当前视口树计算；超过 `max_children` 的长尾合并为有界汇总，避免超大兄弟集合。
- 区块无动效：树就绪时直接按布局坐标放置，扫描期间没有逐帧推进开销。
- 布局阈值与长宽比整改在 `cairn-core` 完成，UI 不重复做全量几何搜索。

### 2.4 测量与报告

- 先构建 release，再记录冷启动、查询、首帧、常驻内存和 Treemap 首屏时间。
- 报告区分“测量值”和“目标值”；未执行或环境不满足时明确写“未验证”。
- 任何优化必须给出前后对比和回退条件，不以单个平均值替代分位数/边界样本。
