# 索引平台设计（Everything 1.5 对齐）

> 本文定义已确认的索引平台方向与设计约束：任意文件夹索引源、3–5 个高频属性索引、只读索引日志，以及配套的搜索与结果工作流范围。需求编号见 [SPEC](../SPEC.md) 的 IDX-11..13、QRY-10、UI-11；这些能力尚未实现，当前状态以 SPEC §3.10 为准。

## 1. 范围与决策

- 对标档位为索引平台档：补齐非 NTFS 索引源、属性索引与只读索引日志；不提供 HTTP/ETP/FTP 供数、Everything Server 多用户共享、动态插件、便携 ZIP 或 Everything IPC 字节兼容。
- 所有索引源由已安装服务独占管理，不引入用户态回退或范围切换。服务保持只读红线。
- 索引源顺序：任意文件夹源先行，随后 FAT/exFAT、ReFS、EFU 文件列表；映射网络盘、远程索引与 SMB 共享保持非目标。
- 属性索引覆盖 3–5 个高频属性，开启后常驻内存目标 ≤160 字节/条；基础配置保持 ≤125 字节/条。
- 索引日志只读、容量有界、可查询与导出，不提供写接口。
- 结果工作流先补 Findbar 与列显隐；Tabs/Sessions、预览/缩略图、多文件重命名与文件操作撤销列为后续。
- 1.5 没有通用 Groups 视图；Cairn 不以结果分组为对标项。

## 2. IndexSource 抽象

NTFS 卷适配器保持现有 `$MFT` 流式扫描、USN 增量与五态状态机。其他来源实现同一组能力，但可以使用各自的扫描与监控机制。

### 2.1 接口职责

每个索引源提供：

- 稳定身份：来源 id、类型、根路径或卷、显示名。身份不得使用可复用的盘符作为唯一键。
- 首次扫描：可取消、可报告进度；扫描完成前不宣称 `Synced`。
- 变更监控：原生监控优先；文件夹源使用变更缓冲，缓冲溢出时降级为全量重扫。
- 重扫：手动、定时与“错过计划后的启动重扫”。
- 状态：每源独立的 `Synced` / `CatchingUp` / `Rebuilding` / `SnapshotMode` / `Offline`。
- 排除与总计：查询期排除规则对所有源一致；总计按源与最高命中点计算。
- Treemap：树数据来自源索引，不触发本地扫描。

### 2.2 文件夹源（首期）

- 以路径而非物理卷跟踪；盘符复用不得让两个来源互相覆盖，路径规范化后必须唯一。
- 无需管理员权限即可配置，但索引由 `LocalSystem` 服务执行，只能覆盖服务身份可读取的路径。用户会话内挂载的云盘、虚拟文件夹或映射盘若服务不可见，首期不支持；需要在设计验证阶段实测并明确界面提示。
- 首次扫描完成后进入监控；监控不可用时按计划重扫，不能把“仅扫描”误标为实时同步。
- 来源离线时保留索引并显式标注 `Offline`，恢复后按源重扫或继续监控。
- 文件夹源没有 NTFS FRN；记录身份使用源内稳定 id（路径标识或序号），硬链接语义不适用。

### 2.3 查询与作用域

- 源出现在侧栏位置中，选中即限定该来源；无作用域的文本查询跨源合并，文本less 全量视图要求唯一活动源，沿用现有“单一活动卷”语义。
- 每个来源保留自己的 generation、预排序版本与排除 epoch；跨源结果合并不得混用某源的视图快照。
- 盘符作用域只适用于 NTFS 卷；文件夹源使用来源作用域，不引入 Everything 的远程索引语法或 IPC 兼容。

## 3. 属性索引

- 侧表以（来源，记录）为键，不扩张 `FileRecord` 定长布局；属性注册表只收录已确认的高频属性，首批建议为长度、作者、标签、尺寸与帧率。
- 抽取在 Worker 进程执行，带超时、崩溃隔离与失败降级；抽取失败不得阻塞文件名查询或污染索引状态。
- 属性索引默认关闭；未开启时不分配侧表，不改变基础内存预算。
- 开启后以 400 万条语料单独实测内存与查询；目标为 ≤160 字节/条。100k 基础基准门禁不替代该实测。
- 属性值变化沿来源的变更通道更新；无法感知的来源在重扫时更新。属性函数在索引未开启时明确降级，不静默返回空结果。

## 4. 只读索引日志

- NTFS 来源由 USN 派生，文件夹等来源由扫描与监控事件派生；记录创建、重命名、移动、修改、删除、时间与新旧路径。
- 容量有界并轮转；通过只读管道与 CLI 查询、导出，不提供写接口，不破坏服务只读红线。
- 日志只保存在本机，不进入遥测或网络；路径属于敏感信息，导出由用户显式触发。
- GUI 文件操作撤销不在本期；日志只提供外部变更追溯与排障基础。

## 5. 搜索与结果工作流

- QRY-10：拼音（全拼/首字母）、忽略标点/空白、变音符号、长度/属性/层级/去重/唯一等高频函数与多键排序。正则保持线性时间引擎，不引入捕获列与自定义宏。
- UI-11：结果内查找（`Ctrl+F`、`F3`/`Shift+F3`、高亮与循环）与列显隐/表头右键菜单；列显隐持久化，并且不得破坏虚拟滚动。
- Tabs/Sessions、预览/缩略图、多文件重命名、文件操作撤销不在本期，后续按单独里程碑评估。

## 6. 内存与性能

- 基础索引保持 ≤125 字节/条；属性索引开启后目标 ≤160 字节/条；每个预排序列仍为 4 字节/条。
- 文件夹等扫描型来源需要自己的变更缓冲与重扫预算；查询不得因来源数量增加而物化全量结果。
- 每个来源的全量视图按自己的快照与预排序序列分页；跨源合并只处理查询实际需要的范围。
- 属性索引与多源索引同时开启时必须重新跑 400 万条内存与查询基准，并纳入发布前实测。

## 7. 风险

| 风险 | 触发条件 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 服务身份不可见用户挂载 | 云盘、虚拟文件夹或映射盘只在用户会话中可见 | 文件夹源无法索引或读到的内容与用户预期不一致 | 首期只承诺服务可读路径；界面显式提示；验证阶段实测 |
| 盘符与路径复用 | 外接盘换盘符或同名路径 | 两个来源互相覆盖或查询串数据 | 来源 id 不使用盘符；路径规范化；重扫时校验 |
| “Synced”语义被稀释 | 扫描型来源没有实时监控 | 用户把最后一次扫描当作实时状态 | 每源独立状态；监控不可用时明确标注扫描时间与过期风险 |
| 属性处理器挂起 | 第三方 Property Handler/IFilter 卡死 | 属性索引停摆或 Worker 崩溃 | Worker 隔离、超时、失败降级 |
| 内存预算突破 | 属性、多源与内容索引同时开启 | 4M 目标被突破，服务换页 | 按源/属性预算；属性默认关闭；发布前 4M 实测 |
| 安全面扩大 | 为兼容 Everything 引入远程/网络供数 | 只读服务被外部枚举或 DoS | 保持非目标；只保留本地只读管道与 CLI |

## 8. 验证顺序

1. `IndexSource` 抽象与文件夹源端到端：扫描、监控、状态、排除、总计、Treemap 与回归测试。
2. 搜索语言与结果工作流：拼音、忽略标点/空白、层级/去重函数、多键排序、Findbar、列显隐。
3. 属性索引首批 3–5 个属性，完成 400 万条内存与查询实测。
4. 只读索引日志与查询/导出。
5. FAT/exFAT、ReFS、EFU 按同一抽象跟进；网络/远程保持非目标。
